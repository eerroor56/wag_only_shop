# Архитектура WAG Shop

## Компоненты

```
 Telegram-клиент                    Сервер (один Node.js процесс)                  PostgreSQL
┌──────────────┐  HTTPS + initData ┌──────────────────────────────────────┐      ┌──────────────┐
│ Mini App     │ ────────────────► │ Fastify: /api/*   (REST)             │ ───► │ users        │
│ (React)      │                   │          /        (статика Mini App) │      │ products     │
│ Админ-панель │ ────────────────► │          /admin/  (статика админки)  │      │ product_imgs │
└──────────────┘                   │          /uploads (фото)             │      │ carts/items  │
        ▲                          │ grammY: /api/telegram/webhook        │      │ orders/items │
        │ сообщения бота           │ Воркер рассылки (очередь в БД)       │      │ broadcasts   │
 Telegram Bot API ◄────────────────│ Повтор уведомлений о заказах         │      └──────────────┘
                                   └──────────────────────────────────────┘
```

Один процесс и один домен: нет CORS, проще деплой. Frontend и backend собираются отдельно, их можно
разнести по разным серверам или отдавать статику через CDN (`SERVE_STATIC=false`).

## Ключевые решения

**Корзина хранится на сервере**, а не в localStorage. Корзина переживает переустановку Telegram и смену
устройства, а заказ формируется из корзины в БД, поэтому клиент физически не может передать свою цену или
состав.

**Деньги в копейках (integer).** Нет ошибок округления float; при необходимости можно продавать с копейками
без миграции.

**Цена задаётся администратором.** `price` — финальная цена продажи. `old_price` и `discount_percent` нужны
только для отображения: процент можно указать вручную, иначе он вычисляется из старой цены. Кнопка
«Рассчитать цену со скидкой» в админке лишь подставляет значение в поле, и администратор может его
изменить.

**Snapshot в заказах.** `order_items` хранит название и цену на момент покупки; `product_id` при удалении
товара становится `NULL`. Старые заказы не меняются при правках каталога.

**Фото загружаются до сохранения товара.** `POST /api/admin/images` создаёт запись `product_images` с
`product_id = NULL`. При сохранении товара передаётся упорядоченный список `imageIds` и `mainImageId`, и
сервер атомарно прикрепляет фото, задаёт порядок и главное фото, удаляя исключённые. Не прикреплённые за
сутки загрузки удаляет фоновая задача. Уникальный частичный индекс гарантирует ровно одно главное фото у
товара.

**Хранилище — интерфейс `StorageDriver`.** В БД хранятся ключи (`products/2026/11/<uuid>.webp`), URL
строит драйвер (локальный диск или S3). Переезд на CDN меняет только конфигурацию.

**Очередь рассылки в PostgreSQL.** При создании рассылки снимается snapshot получателей в
`broadcast_recipients`. Воркер берёт пачки по 100 и отправляет с заданной скоростью (25 сообщений/с при
лимите Telegram ~30/с); 429 обрабатывает плагин auto-retry. Статус получателя и счётчик обновляются в одной
транзакции, поэтому после перезапуска отправка продолжается без дублей в статистике. Advisory lock
гарантирует единственный воркер при нескольких экземплярах. Ошибки 403 и «chat not found» помечают
пользователя `is_blocked`; при `/start` или событии `my_chat_member` он снова становится активным.

**Уведомления владельцу надёжны.** Заказ фиксируется в БД до отправки уведомления; ответ клиенту не ждёт
Telegram. Если отправка не удалась, `owner_notified_at` остаётся пустым, и задача повторяет попытку раз в
минуту (до 5 раз в течение суток).

**Авторизация без сессий.** Каждый запрос несёт initData (`Authorization: tma …`), которую сервер
проверяет подписью бота. Пользователь создаётся или обновляется при первом запросе; `last_seen_at`
обновляется не чаще раза в 5 минут (кеш в памяти), чтобы не писать в БД на каждый запрос.

**Dev без обхода авторизации.** Для разработки в браузере `npm run dev:init-data` подписывает тестовую
initData настоящим `BOT_TOKEN`, поэтому в коде нет режима, который отключает проверку.

## Модель данных

```
users 1──1 carts 1──* cart_items *──1 products 1──* product_images
  │                                      │
  1                                      │ (SET NULL)
  *                                      │
orders 1──* order_items ─────────────────┘

broadcasts 1──* broadcast_recipients *──1 users
```

| Таблица | Назначение |
| --- | --- |
| `users` | Telegram ID, username, имя, `created_at`, `last_seen_at`, `is_blocked` |
| `categories` | Группы товаров: `name`, `name_key` (уникальный ключ в нижнем регистре, считается в приложении), `sort_order` |
| `products` | Название, описание, `price`, `old_price`, `discount_percent`, `attributes` (JSONB), `sizes`, `stock` (JSONB, остатки по размерам) и `stock_total`, `title_sort` (генерируемый ключ сортировки/поиска), `category_id` (SET NULL), `is_active`, `sort_order` |
| `product_images` | `storage_key`, `thumb_key`, размеры, `sort_order`, `is_main` |
| `carts`, `cart_items` | Корзина пользователя, уникальная пара (cart, product), количество 1–99 |
| `orders` | Номер (с 1001), имя, телефон (E.164), username-snapshot, сумма, статус, ключ идемпотентности, статус уведомления |
| `order_items` | Snapshot названия и цены, количество, сумма позиции |
| `broadcasts`, `broadcast_recipients` | Рассылка и очередь доставки |

Ограничения целостности дублируются в БД через CHECK: цена ≥ 0, старая цена больше текущей, скидка от 1 до
99% и только при наличии старой цены, количество в корзине от 1 до 99.
